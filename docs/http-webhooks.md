# HTTP и webhooks

## Зачем

Webhook Center принимает чужие HTTP-запросы. Надо понимать, что именно пришло,
и сохранить это без потерь.

JSON-парсер меняет исходное представление body. Поэтому одного готового объекта
для инспектора и replay недостаточно.

## Части запроса

| Часть          | Что это                                             |
| -------------- | --------------------------------------------------- |
| Method         | Намерение клиента: GET, POST, PUT, PATCH или DELETE |
| Path           | Путь к ресурсу                                      |
| Query          | Параметры после `?` в URL                           |
| Headers        | Служебные данные                                    |
| Content-Type   | Формат body                                         |
| Content-Length | Размер body в байтах                                |
| Body           | Отправленные данные; может отсутствовать            |

Query и body — разные вещи. Например, `?attempt=2` находится в URL, а JSON — в
body.

## Эксперименты

Использовал Browser DevTools, Postman и Postman Echo. Cookies и токены из
примеров удалены.

| Запрос                             | Результат                                            | Вывод                                                    |
| ---------------------------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| GET изображения без body           | `200`, ответ `image/jpeg`, 1414 байт                 | У запроса body не было, а у ответа была картинка         |
| GET `/get?lesson=http&attempt=1`   | `200`, параметры появились в `args`                  | Query остаётся частью URL; `"1"` осталось строкой        |
| POST с форматированным JSON        | `200`, `application/json`, 25 байт                   | Echo разобрал body как JSON; пробелы тоже занимают байты |
| JSON-подобный текст с `text/plain` | `200`, текст попал в `data`, `json: null`            | Скобки сами по себе не делают текст JSON                 |
| POST с form data                   | `200`, `application/x-www-form-urlencoded`, 24 байта | Поля появились в `form`; `100` осталось строкой          |
| POST без body                      | `200`, `Content-Length: 0`, `json: null`             | Пустое body — это ноль байт, а не `{}`                   |

Form data в тесте выглядело так:

```text
colorName=red&number=100
```

Форматированный JSON выглядел так:

```json
{
  "hero": "kiri"
}
```

## Методы

Проверил пять методов через Postman Echo:

| Метод  | Маршрут   | Body | Статус |
| ------ | --------- | ---- | ------ |
| GET    | `/get`    | нет  | `200`  |
| POST   | `/post`   | JSON | `200`  |
| PUT    | `/put`    | JSON | `200`  |
| PATCH  | `/patch`  | JSON | `200`  |
| DELETE | `/delete` | нет  | `200`  |

Echo использует отдельный маршрут для каждого метода, но это его решение. Один
маршрут тоже может принимать разные методы. В Webhook Center это будет
`/hooks/:token`.

Метод показывает намерение. Реальное действие определяет сервер. Echo, например,
ничего не создаёт и не удаляет, а только отражает запрос.

## Статусы

- **2xx** — запрос обработан успешно. В тестах обычно был `200`.
- **4xx** — проблема с запросом или ресурсом. Несуществующий маршрут дал `404`.
- **5xx** — сервер не смог обработать запрос. httpbin один раз дал `503`.

`200` не означает, что body было JSON. Сервер успешно принял JSON, текст, form
data и пустое body.

## Почему нужен raw body

После `parse` и `stringify` могут измениться пробелы, переносы строк и текстовая
запись значений. Объект останется тем же, но байты уже будут другими.

Поэтому Webhook Center должен хранить raw body, метод, path, query, headers,
Content-Type и размер. Разобранный JSON нужен только для удобного просмотра.

Так инспектор покажет настоящий запрос, а replay отправит исходное body.

## Итог

HTTP-запрос — это не только JSON. Нельзя путать query с body, request body с
response body, а пустое body с пустым JSON-объектом.
